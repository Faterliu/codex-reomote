流程：
1. 仓库先跑 `pnpm typecheck` 确认通过。
2. `robocopy` 源码到 `C:\a`，排除 `.git / node_modules / dist / build-logs / android / .pnpm-store`。
3. `pnpm install --frozen-lockfile --node-linker=hoisted`。
4. `expo prebuild --clean --platform android --no-install`（约 4 分钟）。
5. `gradlew assembleRelease --no-daemon`（约 22 分钟）。

环境坑位（重要，下次直接复用）：
- Bash 工具的 PATH 缺 `/usr/bin`，`ls`/`tr`/`dirname` 都会 command not found，需要显式 `export PATH="/usr/bin:/bin:/c/Windows/System32:$PATH"`。
- 从 Bash 调用 `cmd.exe` 会被沙箱拦截，所以 `gradlew.bat` 走不通；改用 Gradle 自带的 POSIX wrapper：`bash ./gradlew`。
- 用 POSIX 版 gradlew 时 `JAVA_HOME` 必须是 POSIX 风格路径（`/c/Users/...`），Windows 反斜杠风格会导致找不到 java。
- `ANDROID_HOME` 传 Windows 路径，同时手写 `android/local.properties` 的 `sdk.dir`（转义反斜杠）更稳。
- `robocopy` 的参数会被 MSYS 转换，需要 `export MSYS2_ARG_CONV_EXCL='*'`。

## 代码审查：模型 / 思考程度 的「记忆」能力

结论：**服务端按 thread 持久化，手机本地完全不存**。

- 写入：`selectModel` / `selectReasoningEffort` → `updateSelectedThreadSettings` → `thread/settings/update` 写回 app-server。
- 服务端：`ThreadSettings` 含 `model` 与 `effort`；`ThreadResumeResponse` 同时返回 `model` 和 `reasoningEffort`。
- 本地：`selectedModelId` / `selectedReasoningEffort` 只是 `useState`，全项目仅 `connectionStorage.ts`
  使用 `expo-secure-store` 且只存 URL/token。

发现两个疑似 bug（见 `apps/mobile/src/hooks/codex-app-server/api.ts`）：

1. `resumeThreadWithInitialTurnPage()` 丢弃了 `resumed.model`，只带出 `reasoningEffort`
   → 模型永远不会在重开会话时回填。
2. 该函数对 `idle` / `systemError` 状态的 thread 提前 return（不 resume，`reasoningEffort: undefined`），
   而 `openThread` 只在 `undefined` 时才跳过赋值 → 切到 idle 会话会**沿用上一个会话的思考程度**。
   且 `turn/start` 每次显式带 `effort`，所以界面显示错就会真的按错的值发出。

未确认项：app-server 是否在 resume/attach 时主动推送 `thread/settings/updated`（客户端该处会同时同步
model+effort）。仅凭生成类型无法判断，需抓真实报文。

待用户确认后再改，改动会需要重新出包。
